# C# code-behind, ViewModel и атрибуты проекта

## Code-behind

Code-behind - это C#-файл рядом с XAML-страницей. Например:

- `FeedPage.xaml` и `FeedPage.xaml.cs`;
- `ProfilePage.xaml` и `ProfilePage.xaml.cs`;
- `ChatPage.xaml` и `ChatPage.xaml.cs`.

Обычно code-behind в проекте делает три вещи:

- вызывает `InitializeComponent()`;
- задает `BindingContext`;
- запускает загрузку данных в `OnAppearing`.

Основная логика вынесена во ViewModel, поэтому code-behind остается коротким.

## `partial class`

Страницы и ViewModel часто объявлены как `partial class`.

`partial` значит, что один класс может быть собран из нескольких файлов. Для XAML-страницы часть класса создается MAUI автоматически из XAML, а в `.xaml.cs` находится ручная часть класса.

Для ViewModel `partial` нужен CommunityToolkit.Mvvm. Генератор кода добавляет свойства и команды в дополнительную часть класса.

## `InitializeComponent()`

`InitializeComponent()` загружает XAML-разметку и создает все элементы страницы.

Этот метод должен вызываться в конструкторе страницы до активной работы с элементами интерфейса.

## `BindingContext`

`BindingContext` задает объект, из которого XAML берет свойства и команды.

Пример:

```csharp
BindingContext = vm;
```

После этого XAML может использовать:

```xml
Text="{Binding Login}"
Command="{Binding SaveProfileCommand}"
```

Если `BindingContext` не задан, привязки страницы не будут находить свойства ViewModel.

## `OnAppearing`

`OnAppearing` вызывается, когда страница появляется на экране.

В проекте он используется для загрузки актуальных данных:

- профиль загружает пользователя и публикации;
- поиск обновляет списки;
- отчеты загружают статистику;
- настройки загружают данные аккаунта.

Так данные обновляются при каждом открытии страницы.

## MVVM-слой

ViewModel хранит состояние экрана:

- текст полей;
- выбранные вкладки;
- коллекции списков;
- флаги загрузки;
- сообщения об ошибках;
- команды для кнопок.

Все ViewModel наследуются от `BaseViewModel` или `ObservableObject`, чтобы интерфейс получал уведомления об изменениях.

## `ObservableObject`

`ObservableObject` приходит из `CommunityToolkit.Mvvm.ComponentModel`.

Он реализует механизм `INotifyPropertyChanged`. Благодаря этому XAML обновляется, когда меняется свойство ViewModel.

## `[ObservableProperty]`

`[ObservableProperty]` ставится над приватным полем.

Пример:

```csharp
[ObservableProperty]
private string login = string.Empty;
```

Генератор создает публичное свойство `Login`. Если присвоить `Login = "user"`, интерфейс получит уведомление и обновит привязки.

Правило именования: поле `login` превращается в свойство `Login`, поле `isBusy` превращается в `IsBusy`.

## `[NotifyPropertyChangedFor]`

`[NotifyPropertyChangedFor]` указывает, какие вычисляемые свойства нужно обновить при изменении основного свойства.

Пример: если меняется вкладка публикации, должны обновиться:

- выбран ли режим заметки;
- заголовок страницы;
- цвет вкладки фото;
- цвет вкладки заметки.

Без этого интерфейс мог бы оставить старый цвет или старый текст.

## `[RelayCommand]`

`[RelayCommand]` превращает метод в команду для XAML.

Пример:

```csharp
[RelayCommand]
private async Task LoadFeed()
```

В XAML эта команда вызывается как:

```xml
Command="{Binding LoadFeedCommand}"
```

Генератор добавляет к имени метода слово `Command`. Метод `LoadFeed` становится командой `LoadFeedCommand`.

Команды могут быть синхронными и асинхронными. Для запросов к API чаще используется `async Task`.

## `[QueryProperty]`

`[QueryProperty]` принимает параметры навигации Shell.

Пример:

```csharp
[QueryProperty(nameof(PostId), "postId")]
```

Если выполнить переход:

```csharp
await Shell.Current.GoToAsync("PostDetailPage?postId=10");
```

то свойство `PostId` во ViewModel получит значение `10`.

В проекте это используется для:

- открытия публикации по `postId`;
- открытия чужого профиля по `userId`;
- открытия чата по `chatId`;
- передачи данных собеседника в чат.

## Навигация через Shell

Основной метод навигации:

```csharp
await Shell.Current.GoToAsync("RouteName");
```

Варианты:

- `//LoginPage` открывает страницу как новую корневую.
- `SettingsPage` открывает страницу поверх текущей.
- `..` возвращает назад.
- `PostDetailPage?postId=5` передает параметр.

Двойной слэш полезен после входа или выхода, когда нельзя оставлять старую страницу в истории.

## `Preferences`

`Preferences.Default` хранит простые локальные значения на устройстве.

В проекте сохраняются:

- ID текущего пользователя;
- логин;
- ссылка на аватар;
- просмотренные сторис.

Это не база данных, а небольшое локальное хранилище настроек.

## `ObservableCollection`

`ObservableCollection<T>` используется для списков, которые отображаются в `CollectionView`.

Если добавить или удалить элемент, интерфейс увидит изменение автоматически.

В проекте такие коллекции используются для:

- публикаций;
- комментариев;
- сообщений;
- пользователей;
- чатов;
- хэштегов;
- избранных публикаций.

## `IValueConverter`

`IValueConverter` преобразует одно значение для XAML.

Метод `Convert` меняет значение при выводе в интерфейс. Метод `ConvertBack` нужен для обратного преобразования, но в проекте чаще не используется.

Примеры:

- строка в видимость;
- дата в текст;
- путь медиа в URL;
- тип сообщения в видимость изображения.

## `IMultiValueConverter`

`IMultiValueConverter` получает несколько значений сразу. В проекте используется для проверки нескольких условий одновременно.

Например, элемент можно показать только если выполнены два или три условия.

## `BindableProperty`

`BindableProperty` используется в пользовательских элементах `AvatarView` и `AppNavBar`.

Обычное C#-свойство не всегда удобно привязывать из XAML. `BindableProperty` делает свойство полноценной частью MAUI-привязок.

Примерные свойства:

- `AvatarView.Source`;
- `AvatarView.Size`;
- `AvatarView.IsSystem`;
- `AppNavBar.Mode`;
- `AppNavBar.Current`.

## Сервисы клиента

Папка `Service` содержит клиентские классы для обращения к API.

Они используют `HttpClient` и скрывают детали HTTP-запросов от ViewModel.

Например, ViewModel вызывает:

```csharp
await _post.GetFeedAsync(userId, mode);
```

А внутри сервиса уже формируется адрес API, отправляется запрос и разбирается JSON.

## DTO

DTO - это объект передачи данных. Он нужен, чтобы передавать между клиентом и сервером только нужные поля.

В проекте DTO используются для:

- сообщений;
- чатов;
- результата подписки;
- отчетов;
- запросов регистрации, входа, публикаций и комментариев.

## API-атрибуты

### `[ApiController]`

Помечает класс как API-контроллер. ASP.NET Core начинает автоматически обрабатывать ошибки модели и параметры запроса.

### `[Route]`

Задает общий путь контроллера.

Пример:

```csharp
[Route("api/[controller]")]
```

`[controller]` заменяется именем контроллера без слова `Controller`.

### `[HttpGet]`, `[HttpPost]`, `[HttpPut]`, `[HttpDelete]`

Задают тип HTTP-запроса:

- `HttpGet` - получить данные;
- `HttpPost` - создать или выполнить действие;
- `HttpPut` - обновить;
- `HttpDelete` - удалить.

Если внутри атрибута есть строка, она добавляется к маршруту.

### `[FromRoute]`

Берет значение из пути.

Пример: в маршруте `api/user/5` число `5` попадает в параметр `id`.

### `[FromQuery]`

Берет значение из строки запроса.

Пример:

```text
api/report/top-posts?from=2026-01-01&to=2026-06-01
```

### `[FromBody]`

Берет объект из тела запроса. Используется при создании публикации, регистрации, входе и отправке сообщений.

## `[JsonIgnore]`

`[JsonIgnore]` запрещает сериализацию свойства в JSON.

В моделях это важно для навигационных свойств Entity Framework. Без него при отправке JSON могли бы появиться циклические ссылки: пользователь содержит публикации, публикация содержит пользователя, пользователь снова содержит публикации.

## Entity Framework методы

В `AppDbContext` используются методы:

- `HasOne` - сущность имеет одну связанную сущность;
- `WithMany` - связанная сущность имеет коллекцию;
- `HasForeignKey` - указывает внешний ключ;
- `OnDelete` - задает поведение при удалении;
- `HasIndex` - создает индекс;
- `IsUnique` - делает индекс уникальным.

Эти настройки определяют структуру и ограничения базы данных.

## `async` и `await`

`async` и `await` используются для операций, которые занимают время:

- HTTP-запросы;
- чтение файлов;
- загрузка картинок;
- сохранение Excel;
- работа с SignalR;
- переходы между страницами.

Пока выполняется операция, интерфейс не должен зависать.

## SignalR-клиент

`ChatHubService` использует `HubConnection`.

Основные идеи:

- подключение создается через `HubConnectionBuilder`;
- клиент подписывается на события сервера;
- при отправке сообщения сервер может уведомить второго участника;
- состояние подключения проверяется перед отправкой.

## Работа с файлами

### `FilePicker`

Используется для выбора изображений. Возвращает файл, из которого можно открыть поток данных.

### `FileSaver`

Используется для сохранения Excel-отчета. На ПК пользователь выбирает место сохранения.

### `MemoryStream`

Используется, когда файл создается в памяти. Например, Excel-отчет сначала собирается как массив байтов, затем сохраняется через `FileSaver`.

## `Toast`

`Toast` показывает короткое уведомление. В проекте используется после сохранения настроек, экспорта и других действий.

## Platform-атрибуты

### `[Activity]`

Android-атрибут в `MainActivity.cs`. Он указывает стартовую активность, тему, режим запуска и обработку изменений конфигурации.

### `[Application]`

Android-атрибут в `MainApplication.cs`. Он указывает основной класс приложения Android.

### `[Register]`

iOS-атрибут для регистрации `AppDelegate`.

Эти файлы обычно не меняются при разработке бизнес-логики.

## Как добавлять новую функцию

Обычно новая функция добавляется по цепочке:

1. Добавить или проверить модель/DTO в `Core`.
2. Добавить метод сервиса в API.
3. Добавить endpoint в контроллер API.
4. Добавить метод клиентского сервиса в MAUI.
5. Добавить свойства и команды во ViewModel.
6. Добавить элементы в XAML.
7. Зарегистрировать страницу или сервис в DI, если они новые.
8. Проверить работу через интерфейс и через Swagger.

## Частые ошибки в C#-части

- Метод с `[RelayCommand]` называется `Publish`, а в XAML нужно писать `PublishCommand`.
- После изменения свойства не обновляется зависимое свойство, если не указан `[NotifyPropertyChangedFor]`.
- Страница не получает ViewModel, если ее не зарегистрировали в `MauiProgram.cs`.
- Параметр навигации не приходит, если имя в `[QueryProperty]` не совпадает с именем в маршруте.
- API возвращает циклический JSON, если забыть `ReferenceHandler.IgnoreCycles` или `[JsonIgnore]`.
- Сервис API не вызывается, если не зарегистрирован в `Program.cs`.
- Список не обновляется в интерфейсе, если используется обычный `List<T>` вместо `ObservableCollection<T>`.
- Долгая операция блокирует интерфейс, если не использовать `async` и `await`.
