# Технологии и сложные места проекта

## Общая структура

Проект разделен на три основные части:

- `Social_Network` - клиентское приложение на .NET MAUI.
- `Social_Network.API` - серверная часть на ASP.NET Core Web API.
- `Social_Network.Core` - общие модели данных и DTO, которые используются и клиентом, и сервером.

Такое разделение нужно для того, чтобы интерфейс, серверная логика и общие сущности не смешивались в одном месте. Клиент отвечает за экраны, ввод данных, навигацию и запросы к серверу. API отвечает за хранение, обработку данных, авторизацию, публикации, чаты, подписки и отчеты. Core содержит общие классы вроде `User`, `Post`, `Comment`, `Message`, `Tag`.

## .NET MAUI

.NET MAUI используется для мобильного и настольного интерфейса. В проекте экраны находятся в папке `Social_Network/Social_Network/Views`, а логика экранов вынесена во ViewModel в папку `ViewModels`.

Основные задачи MAUI-части:

- отображение страниц входа, регистрации, ленты, профиля, поиска, чатов, настроек и отчетов;
- адаптация интерфейса под телефон и ПК через `OnIdiom`;
- привязка элементов интерфейса к свойствам ViewModel через `Binding`;
- выполнение команд через `Command`;
- хранение локальных пользовательских данных через `Preferences`;
- выбор файлов через `FilePicker`;
- сохранение Excel-отчета через `FileSaver`;
- показ уведомлений через `Toast`.

## ASP.NET Core Web API

Серверная часть построена на ASP.NET Core. Контроллеры находятся в папке `Social_Network.API/Controllers`.

Контроллеры принимают HTTP-запросы от MAUI-приложения:

- `AuthController` - регистрация, вход, выход.
- `UserController` - профиль, аккаунт, поиск пользователей.
- `PostController` - публикации, лента, поиск по тегам.
- `CommentController` - комментарии и ответы.
- `LikeController` - отметки нравится.
- `SavedPostController` - избранные публикации.
- `SubscriptionController` - подписки и заявки.
- `ChatController` - создание и удаление чатов.
- `MessageController` - сообщения и отмена отправки.
- `ReportController` - статистика и данные для отчетов.
- `UploadController` - загрузка медиафайлов.

Контроллеры не должны содержать всю бизнес-логику. Они вызывают сервисы из папки `Services`, а сервисы уже работают с базой данных.

## Entity Framework Core и SQLite

Для хранения данных используется Entity Framework Core с SQLite. Контекст базы данных находится в `Social_Network.API/Data/AppDbContext.cs`.

`AppDbContext` содержит наборы таблиц:

- `Users` - пользователи;
- `Posts` - публикации;
- `Comments` - комментарии;
- `Likes` - отметки нравится;
- `SavedPosts` - избранное;
- `Subscriptions` - подписки;
- `SubscriptionRequests` - заявки на подписку;
- `Chats` - чаты;
- `Messages` - сообщения;
- `UserSettings` - настройки пользователя;
- `Tags` - хэштеги;
- `PostTags` - связь публикаций и тегов;
- `PostMentions` - отметки пользователей в публикациях.

Связи между таблицами настраиваются в `OnModelCreating`. Там важно понимать `HasOne`, `WithMany`, `HasForeignKey` и `OnDelete`. Например, для подписок используются ограничения удаления, чтобы при удалении одной записи случайно не удалялась цепочка связанных пользователей.

## Миграции

Миграции находятся в папке `Social_Network.API/Migrations`. Они описывают изменения структуры базы данных.

В `Program.cs` сервер вызывает `db.Database.Migrate()`. Это значит, что при запуске API применяет непримененные миграции автоматически. Для курсового проекта это удобно: база создается и обновляется без ручного выполнения команд.

## SignalR

SignalR используется для чатов в реальном времени. На сервере есть `ChatHub`, а на клиенте - `ChatHubService`.

Обычный HTTP-запрос хорошо подходит для загрузки истории сообщений. Но для моментального появления новых сообщений нужен постоянный канал связи. Эту задачу решает SignalR:

- клиент подключается к хабу;
- сервер отправляет событие участникам чата;
- клиент получает сообщение без ручного обновления страницы.

## CommunityToolkit.Mvvm

В проекте активно используется `CommunityToolkit.Mvvm`. Он уменьшает количество однотипного кода во ViewModel.

Главные атрибуты:

- `[ObservableProperty]` создает публичное свойство и уведомляет интерфейс об изменениях.
- `[RelayCommand]` создает команду для кнопок и жестов.
- `[NotifyPropertyChangedFor]` обновляет зависимые свойства.

Например, если меняется выбранная вкладка, должны обновиться цвет кнопки, текст и видимость блоков. Для этого рядом с полем ставятся несколько `[NotifyPropertyChangedFor]`.

## MVVM

Проект построен по схеме MVVM:

- View - XAML-страница с интерфейсом.
- ViewModel - состояние экрана и команды.
- Model - данные, полученные с сервера или из Core.

Преимущество MVVM в том, что XAML почти не содержит логики. Кнопка вызывает команду, поле ввода меняет свойство, список показывает коллекцию. Сама обработка находится во ViewModel.

## Dependency Injection

Зависимости регистрируются в `MauiProgram.cs` и `Program.cs`.

В MAUI:

- сервисы регистрируются через `AddSingleton`;
- ViewModel и страницы регистрируются через `AddTransient`;
- страницы получают нужные ViewModel через конструктор.

В API:

- сервисы регистрируются через `AddScoped`;
- контроллеры получают сервисы через конструктор;
- `AppDbContext` создается через DI и подключается к SQLite.

`Singleton` живет все время работы приложения. `Transient` создается заново при запросе. `Scoped` на сервере обычно живет в пределах одного HTTP-запроса.

## Навигация

Навигация в клиенте сделана через `Shell.Current.GoToAsync`.

Примеры:

- `//FeedPage` открывает страницу ленты как корневую.
- `PostDetailPage?postId=5` открывает детали публикации и передает параметр.
- `..` возвращает на предыдущую страницу.

Параметры маршрута принимаются во ViewModel через `[QueryProperty]`.

## Лента и сортировка

Лента находится в `FeedPage.xaml` и `FeedViewModel.cs`.

Лента поддерживает:

- режим просмотра всех публикаций;
- режим публикаций по подпискам;
- сортировку по дате;
- сортировку по лайкам;
- прямой и обратный порядок;
- мобильное модальное окно фильтра;
- сторис из свежих публикаций пользователей, на которых оформлена подписка.

Сложный момент: после изменения сортировки коллекция `Posts` очищается и заполняется заново уже отсортированными элементами. За счет `ObservableCollection` интерфейс видит изменения автоматически.

## Публикации, хэштеги и отметки

Создание публикаций находится в `CreatePostViewModel.cs`.

Публикация может быть:

- заметкой;
- постом с фотографией;
- постом с описанием;
- постом с хэштегами;
- постом с отмеченными пользователями.

Хэштеги и отметки сначала добавляются в локальные коллекции, а затем отправляются на сервер вместе с публикацией. Это удобно, потому что пользователь может собрать публикацию полностью и только потом нажать `Опубликовать`.

## Приватные профили

В настройках пользователя есть признак закрытого аккаунта. Если профиль закрыт, другой пользователь не видит публикации без подписки.

Сложность здесь в том, что проверка приватности должна быть не только в интерфейсе. Серверная логика также должна учитывать право просмотра, иначе данные можно было бы получить прямым запросом.

## Комментарии и ответы

Комментарии поддерживают ответы на предыдущие комментарии. Для этого в модели используется связь комментария с родительским комментарием.

В базе это выражается через `ParentCommentId`. Если у комментария есть родитель, он является ответом. Если родителя нет, это основной комментарий.

## Избранное и лайки

Лайки и сохраненные публикации хранятся отдельными таблицами. Это позволяет быстро проверить:

- поставил ли текущий пользователь лайк;
- сохранена ли публикация в избранном;
- сколько всего лайков у публикации;
- какие публикации пользователь сохранил.

В интерфейсе иконки лайка и избранного меняются через свойства ViewModel.

## Медиафайлы

Фотографии загружаются через `UploadController`. Сервер сохраняет файлы в `wwwroot/uploads`, а потом раздает их как статические файлы.

На клиенте путь к медиа проходит через `MediaUrlConverter`. Это нужно, чтобы относительный путь от сервера превратился в полный адрес, который может открыть приложение.

## Чаты и сообщения

Чат состоит из двух частей:

- REST API для создания чата, загрузки истории и отмены отправки;
- SignalR для получения новых сообщений в реальном времени.

Отмена отправки сообщения обычно не удаляет всю историю физически из интерфейса. Сообщение помечается как отозванное или удаляется по правилам сервиса, чтобы история оставалась согласованной у обоих участников.

## Отчеты

Отчеты формируются через `ReportService`.

В проекте есть:

- отчет по статистике пользователя;
- отчет по популярным хэштегам;
- статистика публикаций, лайков, комментариев, сообщений и подписок;
- экспорт в Excel.

Период отчета задается в настройках отчетов. Если период включен, дата начала не должна быть позже даты окончания и не должна быть в будущем.

## Экспорт в Excel

Файл `.xlsx` создается в `ExcelExporter.cs` без сторонних Excel-библиотек. Внутри формируется минимальный OpenXML-архив:

- `[Content_Types].xml`;
- связи документа;
- книга Excel;
- листы;
- стили;
- строки и ячейки.

Сложность в том, что `.xlsx` на самом деле является ZIP-архивом с XML-файлами. Чтобы Excel открыл документ корректно, нужно правильно указать связи, типы содержимого, листы, стили и XML-разметку ячеек.

## Конвертеры

Конвертеры находятся в папке `Converters`.

Они нужны, когда значение из ViewModel нельзя напрямую показать в XAML:

- строка превращается в `bool` для `IsVisible`;
- дата форматируется для отображения;
- относительный URL медиа превращается в полный;
- сообщение определяет, нужно ли показывать картинку;
- несколько условий объединяются через `AllTrueConverter`.

## Ресурсы и стили

Цвета находятся в `Resources/Styles/Colors.xaml`, стили - в `Resources/Styles/Styles.xaml`.

Использование ресурсов через `StaticResource` важно для единого внешнего вида. Например, если изменить `AppBackground`, фон поменяется сразу во всех местах, где используется этот ресурс.

## Адаптивность

Для адаптивности используется `OnIdiom`.

Примеры:

- на телефоне боковое меню скрывается;
- на ПК показывается сайдбар;
- нижняя навигация видна только на телефоне;
- ширина центральной колонки отличается на телефоне и на ПК.

Это позволяет держать один XAML-файл для разных форматов экрана.

## Места, где легко ошибиться

- При изменении ViewModel нужно проверять, что все зависимые свойства обновляются через `[NotifyPropertyChangedFor]`.
- При добавлении новой страницы нужно зарегистрировать ее в `MauiProgram.cs` и маршрут в `AppShell.xaml`.
- При добавлении нового API-метода нужно создать метод в контроллере, сервисе клиента и интерфейсе сервиса.
- При изменении моделей базы нужно создавать миграцию.
- При работе с медиа нельзя сохранять локальный путь устройства как постоянную ссылку для всех пользователей.
- При экспорте Excel нужно следить за XML-экранированием символов `&`, `<`, `>`, `"`.
- При работе с чатами важно не смешивать загрузку истории через HTTP и получение новых сообщений через SignalR.
- При настройке приватности нельзя ограничиваться только скрытием элементов в XAML.
