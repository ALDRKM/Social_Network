# Руководство программиста

## 1. Назначение документа

Документ описывает структуру, запуск, сборку, сопровождение и расширение приложения Social Network. Проект реализован на .NET MAUI и ASP.NET Core Web API, использует SQLite, Entity Framework Core, REST API и SignalR.

![[Снимок экрана 2026-06-30 234220 2.png]]
## 2. Общая архитектура

Приложение состоит из трех основных частей:

- `Social_Network.Core` - общие модели предметной области и DTO;
- `Social_Network.API` - серверная часть ASP.NET Core Web API;
- `Social_Network` - клиентское приложение .NET MAUI.

Клиент обращается к серверу по HTTP через REST API. Для чатов используется SignalR-подключение. Данные хранятся в SQLite-базе `Socialnetwork.db`. Медиафайлы сохраняются в папке `wwwroot/uploads` серверной части.

![[Снимок экрана 2026-06-30 234241 2.png]]
## 3. Структура проекта

### 3.1. Общий проект моделей

Папка: `Social_Network/Social_Network.Core`.

В этом проекте находятся основные классы:

- `User` - пользователь;
- `UserSettings` - настройки приватности и уведомлений;
- `Post` - публикация или заметка;
- `Tag` и `PostTag` - хэштеги и связь публикаций с хэштегами;
- `PostMention` - отметки пользователей в публикациях;
- `Like` - отметки "нравится";
- `Comment` - комментарии и ответы на комментарии;
- `SavedPost` - избранные публикации;
- `Subscription` и `SubscriptionRequest` - подписки и заявки на подписку;
- `Chat` и `Message` - переписки и сообщения.

![[Снимок экрана 2026-06-30 234306 2.png]]
### 3.2. Серверная часть

Папка: `Social_Network/Social_Network.API`.

Основные элементы серверной части:

- `Program.cs` - настройка приложения, сервисов, CORS, SignalR, статических файлов и миграций;
- `Data/AppDbContext.cs` - описание таблиц и связей Entity Framework Core;
- `Controllers` - REST-контроллеры;
- `Services` - бизнес-логика;
- `Hubs/ChatHub.cs` - SignalR-хаб для сообщений;
- `Migrations` - миграции базы данных;
- `wwwroot/uploads` - загруженные изображения.

![[Снимок экрана 2026-06-30 235501 2.png]]
### 3.3. Клиентская часть

Папка: `Social_Network/Social_Network`.

Основные элементы клиентского приложения:

- `Views` - XAML-экраны приложения;
- `ViewModels` - логика экранов по MVVM;
- `Service` - клиентские сервисы для обращения к API;
- `Controls` - переиспользуемые элементы интерфейса;
- `Helpers` - вспомогательные классы;

## 5. Серверная часть

### 5.1. Запуск API

API запускается на адресе `http://localhost:5043`. Для запуска из корня репозитория можно использовать команду:

```powershell
dotnet run --project .\Social_Network\Social_Network.API\Social_Network.API.csproj --urls http://localhost:5043
```

После запуска API становятся доступны REST-маршруты и SignalR-хаб `/hubs/chat`.

![[Снимок экрана 2026-06-30 235651 2.png]]

### 5.2. База данных

Для хранения данных используется SQLite. Контекст базы данных находится в `Social_Network.API/Data/AppDbContext.cs`.

В контексте объявлены таблицы:

- `Users`;
- `Posts`;
- `Comments`;
- `Likes`;
- `SavedPosts`;
- `Subscriptions`;
- `SubscriptionRequests`;
- `Chats`;
- `Messages`;
- `UserSettings`;
- `Tags`;
- `PostTags`;
- `PostMentions`.

При запуске сервер применяет миграции автоматически. Также создается системный пользователь, если он отсутствует.


![[Снимок экрана 2026-06-30 235712 2.png]]
### 5.3. REST API

Основные контроллеры:

- `AuthController` - регистрация, вход и выход;
- `UserController` - профиль, аккаунт, пароль, поиск пользователей, удаление аккаунта;
- `UserSettingsController` - настройки приватности;
- `PostController` - публикации, лента, поиск, теги, удаление;
- `CommentController` - комментарии и ответы;
- `LikeController` - лайки;
- `SavedPostController` - избранное;
- `SubscriptionController` - подписки и заявки;
- `ChatController` - список чатов и создание переписки;
- `MessageController` - сообщения, отметка прочтения и удаление;
- `UploadController` - загрузка изображений;
- `ReportController` - отчеты и статистика.


![[Снимок экрана 2026-06-30 235732 2.png]]
### 5.4. SignalR

Чаты работают через `ChatHub`. Хаб публикуется по адресу:

```text
http://localhost:5043/hubs/chat
```

Клиент подключается к хабу через `ChatHubService`, вступает в группу чата и получает события новых или удаленных сообщений.

## 6. Клиентская часть

### 6.1. MVVM-структура

Клиент построен по шаблону MVVM:

- `View` отвечает за разметку экрана;
- `ViewModel` хранит состояние экрана и команды;
- `Service` отправляет запросы к API;
- модели берутся из общего проекта `Social_Network.Core`.

Регистрация зависимостей выполняется в `MauiProgram.cs`. Там подключаются клиентские сервисы, ViewModel и страницы.

## 7. Сборка и запуск при разработке

Сначала нужно запустить сервер:

```powershell
dotnet run --project .\Social_Network\Social_Network.API\Social_Network.API.csproj --urls http://localhost:5043
```

```powershell
dotnet build .\Social_Network\Social_Network\Social_Network.csproj -f net10.0-windows10.0.19041.0
```

## 8. Миграции базы данных

Миграции находятся в папке `Social_Network/Social_Network.API/Migrations`.

При изменении моделей нужно создать новую миграцию из каталога решения:

```powershell
dotnet ef migrations add ИмяМиграции --project .\Social_Network\Social_Network.API\Social_Network.API.csproj
```

Обновление базы может быть выполнено командой:

```powershell
dotnet ef database update --project .\Social_Network\Social_Network.API\Social_Network.API.csproj
```

В обычном запуске API применяет миграции автоматически через `db.Database.Migrate()`.

## 9. Создание нового функционального раздела

Типовой порядок добавления новой возможности:

1. Добавить или изменить модель в `Social_Network.Core`.
2. При необходимости добавить миграцию в API.
3. Добавить методы в серверный сервис.
4. Добавить или расширить контроллер API.
5. Добавить клиентский интерфейс сервиса в MAUI-проекте.
6. Реализовать клиентский сервис.
7. Создать или изменить ViewModel.
8. Создать или изменить XAML-страницу.
9. Зарегистрировать страницу, ViewModel или сервис в `MauiProgram.cs`.
10. Добавить маршрут в `AppShell.xaml.cs`, если экран открывается через навигацию.
11. Проверить работу на Windows и, при необходимости, на Android.

## 10. Работа с отчетами

Отчеты реализованы через:

- `ReportController` в API;
- `ReportService` на сервере;
- `IReportService` и `ReportService` в клиенте;

## 11. Работа с публикациями

Публикации бывают двух типов: фото-публикация и заметка. Тип определяется перечислением `PostType`.

Создание публикации выполняется через `CreatePostViewModel`, клиентский `PostService`, серверный `PostController` и `PostService` API. Для публикаций поддерживаются изображения, хэштеги, отметки пользователей, лайки, комментарии и сохранение в избранное.

## 12. Работа с подписками и приватностью

Подписки реализованы через модели `Subscription` и `SubscriptionRequest`. Если профиль открыт, подписка оформляется сразу. Если профиль закрыт, создается заявка, которую владелец профиля может подтвердить или отклонить.

Настройка закрытого аккаунта хранится в `UserSettings.IsPrivateAccount`.

## 13. Работа с чатами

Список чатов загружается через `ChatController` и `ChatService`. Сообщения загружаются через `MessageController` и `MessageService`. Для сообщений в реальном времени используется `ChatHub` на сервере и `ChatHubService` на клиенте.

В чате поддерживаются:

- история сообщений;
- отправка текстовых сообщений;
- прикрепление изображения;
- поиск по сообщениям;
- отмена отправки своего сообщения;
- отметка сообщений как прочитанных.

## 14. Ресурсы, иконка и экран загрузки

Ресурсы приложения находятся в `Social_Network/Social_Network/Resources`.

Иконка и экран загрузки задаются в `Social_Network.csproj`:

```xml
<MauiIcon Include="Resources\Splash\mainicon.svg" Color="#EBE7B3" />
<MauiSplashScreen Include="Resources\Splash\mainicon.svg" Color="#EBE7B3" BaseSize="158,158" />
```

Для Windows-исполняемого файла дополнительно используется:

```xml
<ApplicationIcon Condition="$([MSBuild]::GetTargetPlatformIdentifier('$(TargetFramework)')) == 'windows'">Resources\AppIcon\mainicon.ico</ApplicationIcon>
```

## 15. Создание установщика Windows

Установщик собирается через Inno Setup. Скрипт находится в корне репозитория:

```text
installer.iss
```

Скрипт включает:

- опубликованную серверную часть из `publish/api`;
- опубликованную клиентскую часть из `publish/client`;
- файл запуска `publish/start.cmd`;
- иконку приложения;
- ярлыки в меню Пуск и на рабочем столе.

![[Снимок экрана 2026-07-01 001254 2.png]]

Общий порядок подготовки установщика:

1. Опубликовать API в папку `publish/api`.
2. Опубликовать MAUI-клиент Windows в папку `publish/client`.
3. Проверить наличие `publish/start.cmd`.
4. Открыть `installer.iss` в Inno Setup Compiler.
5. Нажать Compile.
6. Проверить созданный `SocialNetworkSetup.exe`.

## 17. Возможные ошибки при разработке

Если клиент не получает данные, проверьте, что API запущен на `localhost:5043`.


Если не отображаются изображения, проверьте папку `wwwroot/uploads` и доступность статических файлов в API.

Если не применились изменения модели, проверьте миграции и состояние базы данных.

Если SignalR-сообщения не приходят в реальном времени, проверьте запуск хаба `/hubs/chat` и подключение клиента через `ChatHubService`.

Если в установщике отображается старая иконка, проверьте `SetupIconFile`, ярлыки в `[Icons]`, `UninstallDisplayIcon`, а также пересоберите опубликованный клиент и сам установщик.

## 18. Поддержка и расширение

При сопровождении проекта рекомендуется придерживаться существующей структуры: модели хранить в `Core`, серверную бизнес-логику в `API/Services`, маршруты в `API/Controllers`, клиентские запросы в `Social_Network/Service`, экранную логику в `ViewModels`, а разметку в `Views`.

Такой порядок упрощает поддержку приложения и позволяет добавлять новые функции без нарушения существующей архитектуры.
